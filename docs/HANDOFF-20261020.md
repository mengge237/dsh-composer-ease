## 3. 开放缺陷：引号（详细读数，别重复踩）

期望：`"你好` 末尾打 `"` → `"你好"`；`“文字` 末尾打 `“` → `“文字“`；选中 `abc` 打 `"` → `"abc"`。

已排除的路径（都有实测读数，别重试同一套）：

1. **0.9.2 的 `isUnbalancedBefore` 在真机无效**。真机在 `keydown` 里读到的 composer 是空的：
   `ed.innerText` 只有 `\n`、`childNodes=1`、`flatText(ed)=''`、`caretOffset=0`、Selection anchor 是 `P` 且 offset 0。
   → Lexical 每次按键重排 DOM，`keydown` 正撞在“旧节点已卸、新节点未建”的空窗上。
2. **`beforeinput` 里 `preventDefault()` 不生效**（2026-10-20 实测）：`beforeinput` 时期读状态是对的
   （日志里 `before:"abc"`、`sel:3` 都正确），但即便 `preventDefault()`，原生编辑照样发生，
   于是“自己插 + 原生插”双份 → `""abc"`、`""""`。
3. **靠 `input` 事后补闭符不可靠**：5 场里只有 1 场触发到补闭符分支，空框与中文引号两场根本没有回调。
   → 说明 Lexical 的 `input` 事件在部分插入路径上不经过我们的监听。

结论与下一步建议：

- 不要在 `beforeinput` 里“拦 + 自己插”，Lexical 不接受取消；
- 需要找到 **Lexical 自己的提交时机**：可选路线是按 `MutationObserver` 观察 `[data-composer-input]`
  的子树变化，在“新增了一个开符文本节点”后补闭符并重设 Range；或者只听 `keydown` 但不读 DOM，
  而是维护一份自己的“文本 + 光标偏移”影子状态（在每次 `beforeinput/input` 里同步，读不到就沿用上一次）。
- 无论走哪条，验收必须用上一节的真机脚本，**五场全绿**才提交：
  空框打引号 / 前方有引号+中文 / 框住普通文字 / Shift 连按 / 中文引号成对。

## 4. 已修的两条（作为参考的修复形状）

- **0.9.4 全角空对 Backspace 只删一侧**：`pairbackspace` 两次删除各派发一次 `input`，
  前删后只剩孤立 `（`，`onInput` 的全角自动补闭符把它补回 `）`。
  修法：删除期间 `suppressInput += 2`。判据：派发几次 input 就抑制几次。
- **0.9.5 单书名号 `〈〉` 漏在家族外**：`PAIRS` / `CLOSERS` / `PAIRED_CHAR` 三处必须同时加成员，
  否则出现“有的路径认、有的不认”。用例覆盖：空框配对、右侧已是闭符则跳过、空对 Backspace 整对删。

- 弹层与候选：`Ctrl+Space` 触发、两字母自动弹、`Tab` 接受、`Enter` 一律放行（不被弹层吃）——都有用例

- 不要把 DSH 内核降到 `<0.1.5-rc.1`，也不要装 `web profile` 以外的 profile 来验这个插件
