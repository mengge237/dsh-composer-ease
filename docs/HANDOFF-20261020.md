## 3. 已收口的缺陷：引号（**读数与旧结论相反，别再按旧的做**）

期望：`"你好` 末尾打 `"` → `"你好"`；`“文字` 末尾打 `“` → `“文字“`；选中 `abc` 打 `"` → `"abc"`。

**取证方法**：监听必须挂在 `window` 的捕获阶段（早于插件自己在 `document` 捕获阶段的处理器），
否则记到的是插件已经改过的状态，读数会骗人。这一条是本次能翻案的前提。

上一份交接的三条否定结论，逐条复核结果：

1. ~~keydown 读内容 —— Lexical 那一刻 DOM 是空的~~ **不成立**。真机在 `keydown` 那一刻读到 `text='"你好'`、
   `caret=3`，`isUnbalancedBefore` 判定完全够用。**影子状态（自维护文本+光标）因此不需要**，别再为它写代码。
2. **`beforeinput` 里 `preventDefault()` 不生效** —— 成立，本次复现确认。所以「拦 + 自己插」永久排除。
3. **靠 `input` 事后补不可靠** —— 成立，而且找到了准确形状：**空框里首次插入 Lexical 根本不派发 `input`**
   （探针读数：只有一条 `beforeinput`，零条 `input`）。这才是「5 场只回调 1 场」的真因。

于是实际生效的两条缺陷是：

- **配对之后光标跑掉**：空框打 `"` 值对（`""`）但 `caret=0`（开符**之前**）。接着打字会打到引号外面；
  连按第三下被「跳过闭符」吞掉（`"""` 只出 `""`）。成因：只写一次 `setSelectionRange`，被 Lexical 的重渲染冲掉。
- **空框打 `“` 只得到 `“`**：补闭符挂在 `onInput` 上，而这一场没有 `input`。

修法（已在 `lib/client.js` 里，判据留在代码注释里）：

- `placeCaretVerified()`：按**绝对偏移**写 + **跨帧校验**（0/16/48/110ms 各读回一次；期间又按键就立刻放手）。
  配对、跳闭符、`onInput` 补闭符三处统一走它。
- `onBeforeInput`：**判定在这里、落地等原生插完再收尾**。不拦默认、不自己插开符；判定是「只插一个」时零干预。
  三条护栏：落地后先读有没有闭符（**幂等**，`onInput` 那条先到也不补第二次）；落地位置的字符不是预期开符就**整条放弃**；
  选区框住那条把原生多插的那一个开符**删掉**（读数：选中 `abc` 打 `“` 曾得 `““abc”`；粘贴是 Lexical 异步落的，
  所以要按梯子反复看）。

## 4. 已修的两条（作为修复形状的参考）

- **0.9.4 全角空对 Backspace 只删一侧**：`pairbackspace` 两次删除各派发一次 `input`，前删后只剩孤立 `（`，
  `onInput` 的全角自动补闭符把它补回 `）`。修法：删除期间 `suppressInput += 2`。判据：派发几次 input 就抑制几次。
- **0.9.5 单书名号 `〈〉` 漏在家族外**：`PAIRS` / `CLOSERS` / `PAIRED_CHAR` 三处必须同时加成员，
  否则出现「有的路径认、有的不认」。用例覆盖：空框配对、右侧已是闭符则跳过、空对 Backspace 整对删。

## 7. 已知边界

- **没验的**：没在真中文输入法（系统 IME 组字窗）上手打过一轮；`insertText`/`imeSetComposition` 只近似了 IME 的落字形状。
  这一项要人肉，30 秒的事。
- 弹层与候选：`Ctrl+Space` 触发、两字母自动弹、`Tab` 接受、`Enter` 一律放行（不被弹层吃）——都有用例
- 语言水印：右下角斜排、角度随语言种数 `θ = min(45, 14 + 12×(n−1))`
- 老 `textarea` 形态 composer 只有离线覆盖，没有真机样本
- 不要把 DSH 内核降到 `<0.1.5-rc.1`，也不要装 `web profile` 以外的 profile 来验这个插件
